# Хранилище файлов: зачем нужно и как настроить

## Коротко

В PostgreSQL лежат только **тексты и числа**: профили, задания, ответы, баллы,
календарь, история. **Файлы** — аватары, фото к заданиям, аудио, видео,
голосовые записи учеников — база не хранит. Для них нужно отдельное
**объектное хранилище**.

| Что настроено | Что происходит с файлами |
|---|---|
| Ничего | Файлы пишутся на диск контейнера. На Render **исчезают при каждом деплое**. На VPS живут до пересборки диска и не попадают в бэкапы |
| Объектное хранилище | Файлы лежат отдельно от приложения, переживают деплой, перенос на другой сервер и смену хостинга |

Приложение не падает без хранилища — оно молча уходит в локальный дисковый
режим. Именно поэтому проблему легко не заметить до первого деплоя.

## Как это работает

```
1. Браузер  ──POST /api/storage/request-upload-url──▶  наш сервер
2. Сервер   ──подписанная ссылка на 15 минут────────▶  браузер
3. Браузер  ──PUT файл НАПРЯМУЮ в хранилище────────▶  бакет
4. Позже:   ──GET /api/storage/objects/<id>────────▶  наш сервер ──▶ бакет
```

Два важных следствия:

- **Файл не идёт через наш сервер при загрузке.** Поэтому не упирается в лимиты
  прокси на размер тела запроса — это критично для видео.
- **Бакет должен быть приватным.** Наружу файлы отдаёт наш сервер (шаг 4),
  публичный доступ к бакету не нужен и его не надо включать.

Из шага 3 вытекает единственная неочевидная настройка: браузер обращается к
чужому домену, значит на бакете **обязательно нужно правило CORS**. Без него
загрузка падает с CORS-ошибкой при полностью верных ключах. Это самая частая
причина «всё настроил, а не работает».

## Что нужно прописать

Подходит **любое S3-совместимое** хранилище — провайдер меняется переменными
окружения, править код не нужно.

| Переменная | Что это | Обязательна |
|---|---|---|
| `S3_ENDPOINT` | адрес API хранилища, без имени бакета в пути | да |
| `S3_BUCKET` | имя бакета | да |
| `S3_ACCESS_KEY_ID` | идентификатор ключа доступа | да |
| `S3_SECRET_ACCESS_KEY` | секретный ключ | да |
| `S3_REGION` | регион; для R2 строго `auto` | нет, по умолчанию `auto` |
| `S3_FORCE_PATH_STYLE` | `true` = бакет в пути | нет, по умолчанию `true` |
| `S3_PREFIX` | префикс ключей внутри бакета | нет, по умолчанию `uploads` |

Полный шаблон со всеми переменными проекта: `deploy-vps/env.production.example`.

# Выбор провайдера

Проверено на 30.07.2026.

| Провайдер | Бесплатно | Трафик наружу | Нужна карта |
|---|---|---|---|
| **Cloudflare R2** | 10 ГБ навсегда, 1 млн операций записи и 10 млн чтения в месяц | **бесплатный, без лимита** | да, при подключении R2 |
| **Backblaze B2** | первые 10 ГБ всегда бесплатно | бесплатно до 3× объёма хранения | обычно да |
| **MinIO на своём VPS** | сколько есть диска | ваш трафик | **нет** |

**Рекомендация — Cloudflare R2.** У проекта видео и аудио: трафик наружу тут
дороже места, а у R2 он бесплатный. 10 ГБ хватает надолго — аватары сжимаются
до 256×256.

**Если карту привязывать не хотите** — вариант с MinIO на VPS (раздел 3). Но
пока проект на Render, локальный диск не подходит, так что до переезда придётся
либо принять исчезновение файлов при деплое, либо взять R2/B2.

# 1. Cloudflare R2 (рекомендуется)

## 1.1. Создать бакет

1. Зарегистрируйтесь / войдите на [dash.cloudflare.com](https://dash.cloudflare.com).
2. В левом меню выберите **R2** (может называться **Storage & databases → R2**).
3. Нажмите кнопку подключения R2 и пройдите checkout. Карта нужна, но в пределах
   бесплатного объёма списаний не будет.
4. **Create bucket**.
   - **Bucket name**: например `english-learning-media`. Это значение пойдёт
     в `S3_BUCKET`.
   - **Location**: ближайший к серверу регион (для Европы — EU).
   - Остальное оставьте по умолчанию.
5. Нажмите **Create bucket**.

> Публичный доступ (Public Development URL / custom domain) **включать не надо** —
> файлы отдаёт наше приложение.

## 1.2. Узнать endpoint

На странице бакета откройте **Settings** и найдите **S3 API**. Адрес выглядит так:

```
https://<длинный_account_id>.r2.cloudflarestorage.com/english-learning-media
```

В `S3_ENDPOINT` укажите его **без имени бакета**:

```
S3_ENDPOINT=https://<длинный_account_id>.r2.cloudflarestorage.com
```

## 1.3. Создать ключи доступа

1. На главной странице R2 справа — **Manage R2 API Tokens** (или **API → Manage
   API tokens**).
2. **Create API token**.
   - **Token name**: например `english-learning-app`.
   - **Permissions**: **Object Read & Write**.
   - **Specify bucket(s)**: выберите только созданный бакет — так ключ не имеет
     доступа к остальным.
   - **TTL**: без срока (или поставьте напоминание о ротации).
3. **Create API Token**.
4. Скопируйте **Access Key ID** и **Secret Access Key**.

> **Secret Access Key показывается один раз.** Не закроете страницу — потеряете
> ключ, и придётся создавать новый. В чат ключи не присылайте.

## 1.4. Настроить CORS (без этого загрузка не работает)

1. Страница бакета → **Settings** → блок **CORS policy** → **Add CORS policy**
   (или **Edit**).
2. Вставьте JSON, заменив домены на свои:

```json
[
  {
    "AllowedOrigins": [
      "https://ваш-проект.onrender.com",
      "https://ваш-домен"
    ],
    "AllowedMethods": ["GET", "PUT", "HEAD"],
    "AllowedHeaders": ["content-type"],
    "ExposeHeaders": ["etag"],
    "MaxAgeSeconds": 3600
  }
]
```

3. Сохраните.

Про этот список:

- В `AllowedOrigins` — **точные origin'ы**, откуда открывается приложение
  (схема + домен, без пути и без слэша на конце). Нужен и адрес Render, и
  будущий домен VPS. Для локальной отладки добавьте `http://localhost:5000`.
- `PUT` — это шаг 3 схемы выше, загрузка. Без него не будет работать ничего.
- `AllowedHeaders: ["content-type"]` обязателен: браузер отправляет `Content-Type`,
  и preflight должен его разрешить.

## 1.5. Прописать переменные

**На Render:** сервис → вкладка **Environment** → **Add Environment Variable**,
добавьте по одной. После сохранения Render перезапустит сервис.

```
S3_ENDPOINT           https://<account_id>.r2.cloudflarestorage.com
S3_BUCKET             english-learning-media
S3_ACCESS_KEY_ID      <Access Key ID>
S3_SECRET_ACCESS_KEY  <Secret Access Key>
S3_REGION             auto
S3_FORCE_PATH_STYLE   true
S3_PREFIX             uploads
```

**На VPS:** те же строки в `/opt/v2/app/.env`, затем:

```bash
sudo chmod 600 /opt/v2/app/.env
sudo systemctl restart v2
```

`S3_REGION=auto` для R2 обязателен: любой другой регион даёт ошибку подписи.

Переходите к разделу **Проверка**.

# 2. Backblaze B2

1. Зарегистрируйтесь на [backblaze.com](https://www.backblaze.com/sign-up/cloud-storage).
2. **B2 Cloud Storage → Buckets → Create a Bucket**.
   - **Files in Bucket**: **Private**.
   - Имя бакета глобально уникально — добавьте суффикс, если занято.
3. В списке бакетов посмотрите **Endpoint**, например
   `s3.us-west-004.backblazeb2.com`. В переменную пишется со схемой:
   `S3_ENDPOINT=https://s3.us-west-004.backblazeb2.com`.
4. **Application Keys → Add a New Application Key**.
   - **Allow access to Bucket(s)**: только ваш бакет.
   - **Type of Access**: **Read and Write**.
   - Скопируйте `keyID` → `S3_ACCESS_KEY_ID` и `applicationKey` →
     `S3_SECRET_ACCESS_KEY` (показывается один раз).
5. **Регион** — часть endpoint'а: из `s3.us-west-004…` следует
   `S3_REGION=us-west-004`.
6. **CORS**: в веб-интерфейсе B2 настройка CORS ограничена, поэтому правило
   ставится через CLI:

```bash
# Установка CLI: pip install b2  (или см. docs.backblaze.com)
b2 account authorize <keyID> <applicationKey>
b2 bucket update --cors-rules '[
  {
    "corsRuleName": "app-uploads",
    "allowedOrigins": ["https://ваш-проект.onrender.com"],
    "allowedOperations": ["s3_put", "s3_get", "s3_head"],
    "allowedHeaders": ["content-type"],
    "exposeHeaders": ["etag"],
    "maxAgeSeconds": 3600
  }
]' <имя-бакета> allPrivate
```

7. Переменные — как в разделе 1.5, но с региональным значением `S3_REGION`.

# 3. MinIO на своём VPS (полностью бесплатно, без карты)

Вариант для этапа, когда проект уже переехал на VPS. Файлы остаются на вашем
диске, но лежат отдельно от кода приложения и переживают пересборку.

```bash
# 1. Запустить MinIO рядом с Postgres
sudo mkdir -p /opt/v2/minio-data
docker run -d --name v2-minio --restart unless-stopped \
  -p 127.0.0.1:9000:9000 -p 127.0.0.1:9001:9001 \
  -e MINIO_ROOT_USER=ЗАМЕНИТЬ_ЛОГИН \
  -e MINIO_ROOT_PASSWORD=ЗАМЕНИТЬ_ПАРОЛЬ_МИН_8_СИМВОЛОВ \
  -v /opt/v2/minio-data:/data \
  quay.io/minio/minio server /data --console-address ":9001"

# 2. Создать бакет через клиент mc
docker run --rm --network host --entrypoint sh quay.io/minio/mc -c "
  mc alias set local http://127.0.0.1:9000 ЗАМЕНИТЬ_ЛОГИН ЗАМЕНИТЬ_ПАРОЛЬ_МИН_8_СИМВОЛОВ &&
  mc mb --ignore-existing local/media"
```

Переменные в `.env`:

```
S3_ENDPOINT=http://127.0.0.1:9000
S3_BUCKET=media
S3_ACCESS_KEY_ID=ЗАМЕНИТЬ_ЛОГИН
S3_SECRET_ACCESS_KEY=ЗАМЕНИТЬ_ПАРОЛЬ_МИН_8_СИМВОЛОВ
S3_REGION=us-east-1
S3_FORCE_PATH_STYLE=true
S3_PREFIX=uploads
```

**Важное отличие MinIO.** Порт 9000 закрыт на localhost, значит браузер не может
класть файл напрямую в хранилище. Варианты:

- **Проще:** отдать MinIO поддомен через Caddy (`storage.ваш-домен` →
  `127.0.0.1:9000`), указать этот адрес в `S3_ENDPOINT` и настроить CORS
  (`mc admin config set` / переменная `MINIO_API_CORS_ALLOW_ORIGIN`).
- **Иначе** загрузка уйдёт в локальный дисковый фолбэк, и смысла в MinIO не
  будет.

По этой причине для Render/раннего этапа R2 удобнее: там всё работает сразу.

# Проверка

Не проверяйте настройку «на глаз» через интерфейс — в проекте есть скрипт,
который проходит весь путь и говорит, что именно не так:

```bash
# На VPS (из папки проекта)
node scripts/storage-check.mjs --origin https://ваш-домен

# На Render: Service -> Shell
node scripts/storage-check.mjs --origin https://ваш-проект.onrender.com

# Локально, если переменные в .env
pnpm storage:check
```

Скрипт по шагам проверяет: заданы ли переменные → запись объекта → чтение
метаданных и сохранение `Content-Type` → скачивание и побайтовую сверку →
работу подписанной ссылки → **CORS-preflight** → удаление тестового объекта.
Зависимостей у него нет, сборка не нужна.

Успешный прогон заканчивается строкой `Итог: хранилище настроено правильно.`
После этого загрузите аватар в профиле и добавьте фото к заданию — файлы должны
остаться на месте после `systemctl restart` или нового деплоя.

## Частые ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `SignatureDoesNotMatch` | неверный секретный ключ либо регион | для R2 поставьте `S3_REGION=auto`; пересоздайте ключ |
| Загрузка падает, в консоли браузера CORS-ошибка | нет правила CORS на бакете | раздел 1.4; в `AllowedOrigins` точный origin, в методах `PUT` |
| `403 Access Denied` при записи | у ключа только чтение | пересоздайте ключ с правами **Object Read & Write** |
| `NoSuchBucket` | опечатка в имени или endpoint другого аккаунта | сверьте `S3_BUCKET` и `S3_ENDPOINT` |
| `AuthorizationHeaderMalformed`, `InvalidRequest` | не тот стиль адресации | переключите `S3_FORCE_PATH_STYLE` |
| Файлы грузятся, но исчезают после деплоя | переменные не подхватились, работает локальный фолбэк | запустите скрипт проверки: он скажет, чего не хватает |
| Картинка не отображается / аудио не играет | потерялся `Content-Type` | загрузите файл заново: тип сохраняется при загрузке |

# Что было изменено в коде

Раньше слой хранилища был жёстко завязан на Google Cloud Storage (а до этого —
на sidecar Replit Object Storage). Теперь он S3-совместимый, и провайдер
меняется переменными окружения.

- `artifacts/api-server/src/lib/s3Client.ts` — **новый**. Подпись AWS Signature
  V4 на встроенном `crypto`, без `@aws-sdk/*`: в `build.mjs` эти пакеты
  исключены из бандла, а новая зависимость потребовала бы менять
  `pnpm-lock.yaml` и ломала бы `pnpm install --frozen-lockfile`.
- `artifacts/api-server/src/lib/s3Client.test.ts` — **новый**. Проверка подписи
  на официальных тестовых векторах AWS.
- `artifacts/api-server/src/lib/objectStorage.ts` — переписан на S3. Путь
  объекта больше не вычисляется разбором подписанного URL: раньше это зависело
  от домена конкретного провайдера.
- `artifacts/api-server/src/lib/objectAcl.ts` — убрана зависимость от Google
  SDK. Политика доступа лежит в метаданных объекта (`x-amz-meta-acl-policy`),
  поэтому бакет остаётся приватным.
- `artifacts/api-server/src/routes/storage.ts` — новая проверка конфигурации;
  локальный фолбэк сохранён. Исправлены две ошибки:
  1. локальный режим отдавал **все** файлы как `image/jpeg`, из-за чего
     загруженные аудио и видео не проигрывались — теперь тип сохраняется рядом
     с объектом;
  2. ссылка для локальной загрузки собиралась из заголовка `Host`, который
     внутренний reverse proxy переписывает на `localhost:8080` — клиент получал
     недостижимый адрес. **Это и была причина, по которой presigned-загрузку
     аватара когда-то откатили на multer.** Теперь ссылка относительная.
- `artifacts/english-learning/app/(main)/profile.tsx` — аватар грузится тем же
  presigned-потоком, что остальные медиа. До этого он шёл через multer на
  локальный диск, то есть **на Render исчезал при каждом деплое**.
- `scripts/storage-check.mjs` — **новый**. Диагностика настройки.
- `deploy-vps/env.production.example` — **новый**. Раньше документация ссылалась
  на `.env.production.example`, но файла в репозитории не было: его отсекал
  `.gitignore` по маске `.env.*`.

`@google-cloud/storage` намеренно оставлен в `package.json`: он больше не
используется, но его удаление изменило бы лок-файл. Удалить можно отдельно,
вместе с плановым обновлением зависимостей.
