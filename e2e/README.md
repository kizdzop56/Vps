# E2E-прогоны по живому деплою

Настоящий браузер (Chromium через Playwright) заходит в приложение под учителем,
учеником и родителем, обходит экраны и ловит белые страницы, ошибки в консоли и
пятисотки. Рядом — проверки API: вход, роли, доступ без токена, защита роли
учителя.

Аккаунты берутся из `scripts/src/seed.ts` — сид запускается на каждом деплое.

## Локально

```bash
cd e2e
npm install
npx playwright install --with-deps chromium
BASE_URL=https://v1-app-j975.onrender.com npm test
```

Папка намеренно вне pnpm-воркспейса (`pnpm-workspace.yaml` её не включает):
ставится обычным `npm install`, зависимости приложения не задевает.

## В CI

`.github/workflows/e2e.yml` гоняет прогон каждый вечер и по кнопке
(Actions → «E2E-прогон» → Run workflow, можно подставить другой `BASE_URL`).

При падении workflow пишет отчёт в GitHub Issue с меткой `e2e-failure`: один
иссью на все падения, повторные прогоны добавляют комментарий. Оттуда отчёт
читает QA-агент и раскладывает падения по тикетам в ClickUp.

## Добавить проверку

Экраны перечислены в `tests/ui.spec.ts` в `ROUTES`. Новый экран — одна строка в
нужную роль. Для проверок конкретных кнопок опирайтесь на `testID` в коде
приложения (`getByTestId`), а не на текст: текст меняют, не задумываясь о тестах.
