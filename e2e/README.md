# E2E-прогоны по живому деплою

Настоящий браузер (Chromium через Playwright) работает с приложением под
учителем, учеником и родителем. Аккаунты берутся из `scripts/src/seed.ts` — сид
запускается на каждом деплое.

## Что проверяется

**`tests/api.spec.ts`** — API напрямую: healthz, вход под всеми ролями,
`/auth/me`, отказ без токена и с подделанным токеном, защита роли учителя,
валидация email и роли при регистрации.

**`tests/ui.spec.ts`** — быстрый обход: экраны открываются, не показывают белую
страницу, не сыпят ошибками в консоль и не получают отказов от сервера. В отчёт
попадает метод, адрес и код каждого отклонённого запроса вместе с экраном, на
котором он случился.

**`tests/clickAll.spec.ts`** — нажимает КАЖДЫЙ интерактивный элемент на каждом
экране и делит находки по типу:

| Тип | Что значит |
| --- | --- |
| `МЁРТВАЯ КНОПКА` | после нажатия не изменилось ничего: ни экран, ни разметка, ни запросы |
| `ОТКАЗ СЕРВЕРА` | нажатие ушло в API и получило 4xx/5xx |
| `ИСКЛЮЧЕНИЕ` | нажатие уронило JS |
| `ПУСТОЙ ЭКРАН` | перешли по нажатию и попали в пустоту |
| `НЕ НАЖИМАЕТСЯ` | элемент виден, но клик не проходит (перекрыт, вне экрана) |

Выход из аккаунта, удаление и смена пароля намеренно пропускаются: первое
обрывает прогон, остальное портит данные. Список исключений — `SKIP_LABELS`.

## Локально

```bash
cd e2e
npm install
npx playwright install --with-deps chromium

# быстрый прогон
BASE_URL=https://v1-app-j975.onrender.com npx playwright test tests/api.spec.ts tests/ui.spec.ts

# нажать все кнопки (долго)
BASE_URL=https://v1-app-j975.onrender.com npx playwright test tests/clickAll.spec.ts
```

Папка намеренно вне pnpm-воркспейса (`pnpm-workspace.yaml` её не включает):
ставится обычным `npm install`, зависимости приложения не задевает.

## В CI

`.github/workflows/e2e.yml` — две job: `smoke` (быстрая) и `clickall` (долгая).
Запуск каждый вечер в 18:00 по Минску и по кнопке: Actions → «E2E-прогон» →
Run workflow. Там же можно подставить другой `BASE_URL` и отключить долгий
прогон.

При падении отчёт уходит в GitHub Issue с меткой `e2e-failure`: один иссью,
повторные прогоны добавляют комментарии. Оттуда отчёт читает QA-агент и
раскладывает находки по тикетам в ClickUp.

## Добавить проверку

Экраны перечислены в `ROUTES` (в обоих ui-файлах) — новый экран это одна строка
в нужную роль. Для проверок конкретных кнопок опирайтесь на `testID` в коде
приложения (`getByTestId`), а не на текст: текст меняют, не задумываясь о тестах.

Чем больше `testID` в приложении, тем понятнее отчёт: элементы без подписи
краулер вынужден описывать координатами.
