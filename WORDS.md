# Раздел «Слова»: тренажёр, повторения, очки

Как устроено изучение слов и словосочетаний после обновления. Документ нужен,
чтобы правки в этом разделе не ломали учебную логику: интервалы, оценки и очки
живут в отдельных модулях и покрыты тестами.

## Что изменилось и почему

Было: одна тренировка — перевернуть карточку и самому нажать «знаю» или «учить».
Для детей это работает плохо: увидев перевод, ребёнок уверен, что знал слово,
хотя вспомнить сам не смог. Плюс за карточки не начислялось ничего (очки давали
только задания), а учить можно было лишь внутри одной колоды.

Стало:

| | Было | Стало |
| --- | --- | --- |
| Упражнения | 1 (самооценка) | 5, подбираются по уровню памяти слова |
| Оценка ответа | ученик сам | сервер по ответу: верно/неверно, попытки, время |
| Повторения | 2 оценки, при ошибке −2 уровня | 4 оценки, мягкое падение, «трудно» спрашивает раньше |
| Очки | нет | за верные ответы + бонус за выученное слово, с дневным потолком |
| Цель дня | только минуты в приложении | ещё и слова: `dailyWordGoal` |
| Вход в учёбу | выбрать колоду вручную | кнопка «Учить слова» — сквозная очередь по всем колодам |
| Слабые слова | тонули в общей очереди | подборка «Сложные слова» |
| Картинки | нет | эмодзи-подсказка на карточке (офлайн, без загрузки) |

## Какие колоды видит ученик

На экране «Слова» ровно три вида колод: присланные учителем, свои и
**тематические**. Уровневых колод (`A1 · …`, `A2 · …`) в списке нет.

В базе каталог разложен по уровням CEFR, и когда экран показывал это как есть,
список рос вместе с каталогом и превращался в кашу. Тематическая колода — это
системная колода **без** `cefrLevel` (см. `pickThemeDecks` в
`app/(main)/flashcards.tsx`); проверка идёт именно по уровню, а не по названию,
потому что поле `theme` есть и у уровневых колод.

Слова уровневых колод не потеряны. `visibleDeckIds()` на сервере не фильтрует
колоды по видимости, поэтому они попадают:

- в **«Учить слова»** — новые слова берутся по уровню подготовки и ниже
  (`levelsUpTo`), повторения возвращаются независимо от уровня;
- в **«Марафон слов»** — строго слова текущего уровня.

То есть слова приходят сами, по мере роста уровня, и перебирать колоды руками не
нужно. Там же живут скрытые колоды `misc_{level}` — слова уровня, у которых нет
своей темы.

## Упражнения

Тип упражнения выбирает сервер (`artifacts/api-server/src/lib/wordExercise.ts`)
по уровню памяти карточки — от узнавания к воспроизведению:

| Уровень памяти | Упражнение | Что делает ученик |
| --- | --- | --- |
| новое слово | `intro` | знакомство: картинка, перевод, пример, озвучка |
| 0 | `choiceRu` | видит английское слово → выбирает перевод |
| 1–2 | `choiceRu` / `choiceEn` | чередуются ~50/50; тип детерминирован (сид = слово + день) |
| 3 | `listen` | слышит слово → выбирает перевод |
| 4–5 | `build` | собирает слово из букв (тапами, без клавиатуры) |

Словосочетания и слова длиннее 12 букв из букв не собираются — вместо этого
аудирование или choiceEn. Отвлекающие варианты берутся из слов того же уровня CEFR;
прочие переводы того же слова в неверные варианты не попадают. Для `choiceEn`
варианты ответа — английские слова из той же подборки.

Чередование на уровнях 1–2 детерминировано: `cardSeed(wordId, day) % 2` — биты
стабильны в течение дня и воспроизводимы в тестах, без `Math.random`. Правило
распространяется на все слова, включая словосочетания и идиомы (там `choiceEn` тоже
допустим, это выбор из вариантов, а не набор текста).

Озвучка бесплатная: Web Speech API на web, `expo-speech` на нативе. Слово
проигрывается автоматически при показе карточки.

Цвет ответа никогда не заливает клавишу целиком: под красным или фиолетовым
терялся сам текст ответа — то единственное, что ученик должен прочитать после
ошибки. Состояние показывают рамка, нижняя грань и круглый значок справа
(`OptionKey` в `components/WordTrainer.tsx`).

## Интервальное повторение

`artifacts/api-server/src/lib/srs.ts`. Уровень памяти 0–5, как и раньше;
выученным слово считается с уровня 4.

| Уровень | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| Интервал | 1 мин | 10 мин | 12 ч | 2 дня | 1 неделя | 30 дней |

Оценки: `again` (−1 уровень, выученное уходит на 3, а не в самое начало),
`hard` (уровень тот же, интервал вдвое короче), `good` (+1), `easy` (+2 и
интервал ×1.4).

Оценку выставляет сервер по ответу ученика (`gradeFromAnswer`): неверно →
`again`; верно со второй попытки или с подсказкой → `hard`; верно с первой
попытки быстрее 4 секунд → `easy`; дольше 12 секунд → `hard`; иначе → `good`.

## Очки и цель дня

За верный ответ 2 очка (`hard` — 1), за слово, впервые дошедшее до «выучено», +5.
Дневной потолок — 60 очков, чтобы очки нельзя было накрутить перелистыванием;
начисленное за день восстанавливается из журнала повторений, отдельной колонки в
БД для этого нет. Очки идут в `users.total_points` — туда же, куда за задания.

Цель дня в словах (`flashcard_settings.daily_word_goal`, по умолчанию 10) —
сколько разных слов ребёнок прошёл за сегодня. Прогресс возвращается вместе с
любой очередью и с каждым ответом, показывается в итогах сессии и в статистике.

## API

| Метод | Ручка | Назначение |
| --- | --- | --- |
| GET | `/api/flashcards/session` | сквозная очередь: повторения + новые слова между ними |
| GET | `/api/flashcards/hard` | «сложные слова»: срывы и низкая точность |
| GET | `/api/flashcards/study/:deckId` | очередь одной колоды (тоже с упражнениями) |
| GET | `/api/flashcards/marathon` | все слова уровня (тоже с упражнениями) |
| POST | `/api/flashcards/review` | оценка карточки, очки, прогресс цели дня |
| GET | `/api/flashcards/stats` | статистика + сегодняшний срез + число сложных слов |
| PATCH | `/api/flashcards/settings` | `dailyNewLimit`, `dailyWordGoal` |

`POST /review` принимает оценку в трёх видах: `answer: { correct, attempts,
elapsedMs, hintUsed }` (основной путь), `grade` (знакомство) и старый
`result: "know" | "dont"` — последний оставлен, чтобы уже развёрнутый клиент
продолжал работать до обновления фронтенда.

Размер сессии: до 24 карточек, из них не больше 6 новых (короткая сессия — детям
тяжело держать внимание дольше). Новые слова вставляются между повторениями.

## Аудит каталога: неверные переводы и примеры

В каталоге попадаются карточки с неверным переводом. Причина — многозначность:
импортёр брал первое значение автоперевода, и в колоде про одежду `suit`
становился «иском». Цена ошибки двойная: ребёнок учит неверное значение, а из
тех же переводов строятся варианты ответа в тренажёре.

### Что именно считается ошибкой

Правила отбора живут в `artifacts/api-server/src/lib/wordAudit.ts` и покрыты
`wordAudit.test.ts` (без БД и сети). Сам прогон — `lib/wordAuditRun.ts`, общий
для страницы и скрипта: если бы логика лежала в двух местах, она бы разъехалась,
и данные правила бы то одна версия проверки, то другая.

Перевод проверяется **в две стороны**, иначе честные синонимы пойдут под нож:

1. `EN→RU`, свежий перевод сверяется с сохранёнными по словам и общему корню
   («костюм» и «костюм, комплект» — один ответ). Совпало — карточка чистая.
2. Не совпало → `RU→EN` на сохранённом переводе. Вернулось исходное слово —
   значит это законное второе значение, не трогаем.
3. Обратный перевод не вернул слово — перевод считается ошибочным и заменяется.

Когда свежий перевод просто не совпал с первым сохранённым, он встаёт в начало
списка: первый элемент показывается на карточке и уходит в варианты ответа.

Пример-предложение обязано содержать само изучаемое слово (с учётом форм:
`run → running`, `study → studies`, `to buy → buy`). Пример без слова стирается:
лучше никакого, чем учащий неверному употреблению. Спорные случаи — неправильные
глаголы (`go → went`) и слова короче трёх букв — помечаются как «не берусь
судить» и остаются на месте.

Проверяются только **системные** колоды: переводы в колодах учителей и учеников
это их данные.

### Способ 1: страница в браузере (работает с телефона)

Задайте в окружении `MAINTENANCE_KEY` — длинную случайную строку. Без неё
маршрута не существует, сервер отвечает 404 на всё. Затем откройте:

```
https://<домен>/api/maintenance/audit-words?key=<ключ>
```

Две кнопки: «Проверить» (только отчёт, ничего не меняет) и «Исправить». Страница
сама идёт по каталогу пачками по 40 слов и показывает прогресс — вкладку нужно
держать открытой. Пачками, а не одним запросом, по двум причинам: перевод тысяч
слов не уложится в таймаут прокси, а частые запросы заодно не дают бесплатному
хостингу уснуть посреди прогона.

Ключ едет в адресной строке, то есть попадает в историю браузера и логи прокси.
Меняйте его после работ.

Под страницей лежит `GET /api/maintenance/audit-words/batch` с параметрами
`key`, `offset`, `limit`, `apply=1`, `deck`, `scope=examples|translations` —
его же можно дёргать руками.

### Способ 2: скрипт (нужен шелл с доступом к базе)

По умолчанию только отчёт:

```bash
pnpm exec tsx artifacts/api-server/src/maintenance/auditWords.ts
pnpm exec tsx artifacts/api-server/src/maintenance/auditWords.ts --apply
```

Ключи: `--limit=N` и `--offset=N` (прогон частями), `--deck=ID` (одна колода),
`--examples-only` / `--translations-only`, `--concurrency=N`.

### Про лимиты перевода

Без `GOOGLE_TRANSLATE_API_KEY` работает бесплатный резервный путь Google
Translate — он душит по частоте. Слова, для которых перевод не пришёл, попадают
в «пропущено» и **не меняются**: молча портить данные из-за сетевой осечки
нельзя. Прогоните такие слова ещё раз позже.

## Схема БД: нужен `pnpm db:push`

Добавлены три колонки (все аддитивные, со значениями по умолчанию, поэтому
прежний код с ними совместим):

- `words.emoji` — картинка-подсказка;
- `user_card_state.lapses` — счётчик срывов, по нему собираются «сложные слова»;
- `flashcard_settings.daily_word_goal` — цель дня в словах.

После деплоя выполнить `pnpm db:push`. До этого раздел «Слова» будет отвечать
ошибкой, потому что запросы читают новые колонки.

Картинки проставляются сидом: `pnpm seed` (или `seedFlashcards()`) заполняет
`words.emoji` из карты `WORD_EMOJI` в `scripts/src/data/flashcards-data.ts` —
в том числе для слов, которые уже лежат в базе. Слова и прогресс учеников
(`user_card_state`) при этом не трогаются.

## Тесты

```bash
pnpm exec tsx --test artifacts/api-server/src/lib/srs.test.ts
pnpm exec tsx --test artifacts/api-server/src/lib/wordExercise.test.ts
pnpm exec tsx --test artifacts/api-server/src/lib/wordAudit.test.ts
pnpm validate:flashcards     # датасет + карта картинок, работает без установки зависимостей
```

Все три теста без зависимостей (`node:test`, `node:assert`) — ни БД, ни express
не поднимают. Проверяют: интервалы и границы уровней, мягкое падение при ошибке,
порог «выучено» и однократность бонуса, дневной потолок очков, отбор сложных
слов, выбор упражнения по уровню, корректность вариантов ответа (верный ровно
один раз, прочие переводы того же слова не предлагаются), плитки букв, сборку
очереди сессии и правила аудита словаря.
