# Раздел «Слова»: тренажёр, повторения, очки

Как устроено изучение слов и словосочетаний после обновления. Документ нужен,
чтобы правки в этом разделе не ломали учебную логику: интервалы, оценки и очки
живут в отдельных модулях и покрыты тестами.

## Что изменилось и почему

Было: одна тренировка — перевернуть карточку и самому нажать «знаю» или «учить».
Для детей это работает плохо: увидев перевод, ребёнок уверен, что знал слово,
хотя вспомнить сам не смог. Плюс за карточки не начислялось ничего (очки давали
только задания), а учить можно было лишь внутри одной колоды.

Стало:

| | Было | Стало |
| --- | --- | --- |
| Упражнения | 1 (самооценка) | 5, подбираются по уровню памяти слова |
| Оценка ответа | ученик сам | сервер по ответу: верно/неверно, попытки, время |
| Повторения | 2 оценки, при ошибке −2 уровня | 4 оценки, мягкое падение, «трудно» спрашивает раньше |
| Очки | нет | за верные ответы + бонус за выученное слово, с дневным потолком |
| Цель дня | только минуты в приложении | ещё и слова: `dailyWordGoal` |
| Вход в учёбу | выбрать колоду вручную | кнопка «Учить слова» — сквозная очередь по всем колодам |
| Слабые слова | тонули в общей очереди | подборка «Сложные слова» |
| Картинки | нет | эмодзи-подсказка на карточке (офлайн, без загрузки) |

## Упражнения

Тип упражнения выбирает сервер (`artifacts/api-server/src/lib/wordExercise.ts`)
по уровню памяти карточки — от узнавания к воспроизведению:

| Уровень памяти | Упражнение | Что делает ученик |
| --- | --- | --- |
| новое слово | `intro` | знакомство: картинка, перевод, пример, озвучка |
| 0–1 | `choiceRu` | видит слово → выбирает перевод |
| 2 | `choiceEn` | видит перевод → выбирает слово |
| 3 | `listen` | слышит слово → выбирает перевод |
| 4–5 | `build` | собирает слово из букв (тапами, без клавиатуры) |

Словосочетания и слова длиннее 12 букв из букв не собираются — вместо этого
аудирование или выбор. Отвлекающие варианты берутся из слов того же уровня CEFR;
прочие переводы того же слова в неверные варианты не попадают. Порядок вариантов
детерминирован (сид = слово + день), поэтому он стабилен в течение дня и
воспроизводим в тестах.

Озвучка бесплатная: Web Speech API на web, `expo-speech` на нативе. Слово
проигрывается автоматически при показе карточки.

## Интервальное повторение

`artifacts/api-server/src/lib/srs.ts`. Уровень памяти 0–5, как и раньше;
выученным слово считается с уровня 4.

| Уровень | 0 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- | --- |
| Интервал | 1 мин | 10 мин | 12 ч | 2 дня | 1 неделя | 30 дней |

Оценки: `again` (−1 уровень, выученное уходит на 3, а не в самое начало),
`hard` (уровень тот же, интервал вдвое короче), `good` (+1), `easy` (+2 и
интервал ×1.4).

Оценку выставляет сервер по ответу ученика (`gradeFromAnswer`): неверно →
`again`; верно со второй попытки или с подсказкой → `hard`; верно с первой
попытки быстрее 4 секунд → `easy`; дольше 12 секунд → `hard`; иначе → `good`.

## Очки и цель дня

За верный ответ 2 очка (`hard` — 1), за слово, впервые дошедшее до «выучено», +5.
Дневной потолок — 60 очков, чтобы очки нельзя было накрутить перелистыванием;
начисленное за день восстанавливается из журнала повторений, отдельной колонки в
БД для этого нет. Очки идут в `users.total_points` — туда же, куда за задания.

Цель дня в словах (`flashcard_settings.daily_word_goal`, по умолчанию 10) —
сколько разных слов ребёнок прошёл за сегодня. Прогресс возвращается вместе с
любой очередью и с каждым ответом, показывается на главной, в итогах сессии и в
статистике.

## API

| Метод | Ручка | Назначение |
| --- | --- | --- |
| GET | `/api/flashcards/session` | сквозная очередь: повторения + новые слова между ними |
| GET | `/api/flashcards/hard` | «сложные слова»: срывы и низкая точность |
| GET | `/api/flashcards/study/:deckId` | очередь одной колоды (тоже с упражнениями) |
| GET | `/api/flashcards/marathon` | все слова уровня (тоже с упражнениями) |
| POST | `/api/flashcards/review` | оценка карточки, очки, прогресс цели дня |
| GET | `/api/flashcards/stats` | статистика + сегодняшний срез + число сложных слов |
| PATCH | `/api/flashcards/settings` | `dailyNewLimit`, `dailyWordGoal` |

`POST /review` принимает оценку в трёх видах: `answer: { correct, attempts,
elapsedMs, hintUsed }` (основной путь), `grade` (знакомство) и старый
`result: "know" | "dont"` — последний оставлен, чтобы уже развёрнутый клиент
продолжал работать до обновления фронтенда.

Размер сессии: до 24 карточек, из них не больше 6 новых (короткая сессия — детям
тяжело держать внимание дольше). Новые слова вставляются между повторениями.

Ручки раздела «Слова» добавлены вручную и в `lib/api-spec/openapi.yaml` не
описаны — как и `session`, `hard`, `marathon`, `assign`. Их типы живут рядом с
вызовами в `artifacts/english-learning/hooks/useFlashcards.ts`, кодогенерация
Orval для них не запускается.

## Учитель собирает колоду

Было: колода создавалась сразу при вводе названия, слова добавлялись только по
одному вручную, а отправить колоду ученику можно было лишь из профиля этого
ученика. Выбрать слова из готового каталога было нельзя.

Стало: конструктор из трёх шагов, `app/(main)/flashcards/new-deck.tsx`.

| | Было | Стало |
| --- | --- | --- |
| Выбор слов | набрать вручную по одному | отметить в каталоге (22 готовые колоды, темы и уровни A1–C2) + свои слова |
| Сохранение | колода писалась в БД при вводе названия | черновик в состоянии экрана, запись одним действием в конце |
| Назначение | по одному ученику из его профиля | мультивыбор учеников, последний шаг конструктора и панель на странице колоды |
| Правка колоды | только удалить целиком | переименовать, убрать отдельное слово, дописать слова из каталога |

### Ручки конструктора

| Метод | Ручка | Назначение |
| --- | --- | --- |
| GET | `/api/flashcards/catalog/words` | каталог слов: `q` (по английскому и по переводу), `theme`, `level`, `deckId`, `excludeDeckId`, `includeOwn`, `limit`, `offset` |
| POST | `/api/flashcards/decks/:id/words/bulk` | сохранить подборку: `wordIds` (копии из каталога) и `words` (ручной ввод) |
| DELETE | `/api/flashcards/decks/:id/words/:wordId` | убрать слово из своей колоды |
| PATCH | `/api/flashcards/decks/:id` | название, иконка, описание своей колоды |
| POST | `/api/flashcards/decks/:id/assign/bulk` | отправить нескольким ученикам; `replace: true` синхронизирует список получателей |

`POST .../words/bulk` отвечает `{ added, skipped, failed }`. `skipped` — дубликаты
(слово уже в колоде или повторяется в самой выборке), `failed` — слова с причиной
отказа по каждому. Запрос не падает целиком из-за одного плохого слова, иначе
учитель терял бы всю собранную подборку.

Лимиты: `BULK_WORD_LIMIT = 300` на слова каталога и `MANUAL_WORD_LIMIT = 50` на
ручной ввод — второй жёстче, потому что каждое такое слово проверяется во внешнем
словаре и переводится через Google Translate.

### Почему слово копируется, а не связывается ссылкой

`words.deckId` — NOT NULL, то есть слово принадлежит одной колоде, а прогресс
ученика висит на `word_id` (`user_card_state`). Поэтому отмеченное в каталоге
слово **копируется** в колоду учителя вместе с транскрипцией, примерами, уровнем
и эмодзи. Так у колоды учителя свой независимый прогресс: ученик, который уже
выучил `apple` в системной колоде «Еда и напитки», в колоде учителя встретит его
как новое слово. Ссылочная схема потребовала бы миграции (`word_id` → many-to-many)
и переписывания расчёта прогресса.

Отбор и раскладка строк — в `artifacts/api-server/src/lib/deckWords.ts` (чистые
функции без БД и сети, покрыты тестами).

### Порядок сохранения и частичный сбой

Конструктор сохраняет в три шага: создать колоду → добавить слова → отправить
ученикам. Если спотыкается второй или третий шаг, уже созданная колода не
удаляется, а подборка не теряется: экран показывает, что именно не прошло, и
даёт повторить — повтор продолжает с места сбоя (id созданной колоды лежит в
`useRef`), а не создаёт вторую такую же колоду.

Старая модалка отправки из профиля ученика (`app/(main)/friend/[id].tsx`)
продолжает работать: форма ответа `GET .../assignees` не менялась.

## Схема БД: нужен `pnpm db:push`

Добавлены три колонки (все аддитивные, со значениями по умолчанию, поэтому
прежний код с ними совместим):

- `words.emoji` — картинка-подсказка;
- `user_card_state.lapses` — счётчик срывов, по нему собираются «сложные слова»;
- `flashcard_settings.daily_word_goal` — цель дня в словах.

После деплоя выполнить `pnpm db:push`. До этого раздел «Слова» будет отвечать
ошибкой, потому что запросы читают новые колонки.

Картинки проставляются сидом: `pnpm seed` (или `seedFlashcards()`) заполняет
`words.emoji` из карты `WORD_EMOJI` в `scripts/src/data/flashcards-data.ts` —
в том числе для слов, которые уже лежат в базе. Слова и прогресс учеников
(`user_card_state`) при этом не трогаются.

## Тесты

```bash
pnpm exec tsx --test artifacts/api-server/src/lib/srs.test.ts
pnpm exec tsx --test artifacts/api-server/src/lib/wordExercise.test.ts
pnpm exec tsx --test artifacts/api-server/src/lib/deckWords.test.ts   # сборка колоды из каталога
pnpm validate:flashcards     # датасет + карта картинок, работает без установки зависимостей
```

`deckWords.test.ts` проверяет сборку колоды: перенос всех полей слова в копию,
отсев дубликатов (и уже лежащих в колоде, и повторов внутри выборки), сохранение
порядка выбора в `sortOrder` без дырок от пропущенных слов, восстановление
порядка после `inArray` и нарезку на партии. Конструктор колоды новых колонок не
добавляет — `pnpm db:push` для него не нужен.

Тесты без зависимостей (`node:test`, `node:assert`) — ни БД, ни express не
поднимают. Проверяют: интервалы и границы уровней, мягкое падение при ошибке,
порог «выучено» и однократность бонуса, дневной потолок очков, отбор сложных
слов, выбор упражнения по уровню, корректность вариантов ответа (верный ровно
один раз, прочие переводы того же слова не предлагаются), плитки букв и сборку
очереди сессии.
